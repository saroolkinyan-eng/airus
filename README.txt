AIRUS WEBSITE + CRM v7

Что изменено
============

Публичный сайт
- Перестроен первый экран: главный оффер, цена от 150 ₽/м², понятные CTA и короткая 3-шаговая форма.
- Исправлена логика адресов: список домов больше не перезаписывается вторым справочником.
- Убрано дублирующее поле «Дом». Адрес выбирается один раз.
- Добавлен ручной ввод, если ЖК или дома нет в справочнике.
- Телефон: type=tel, inputmode, autocomplete и маска +7.
- Кнопка отправки блокируется на время запроса; сетевые ошибки показываются пользователю.
- После успешной отправки отображается отдельный экран подтверждения с номером заявки.
- Добавлен honeypot и серверный rate limit от простого спама.
- Удалены публичные данные админки и технические тексты.
- Удалён устаревший блок «Новости».
- Добавлены «Как это работает», основной тариф, свёрнутые дополнительные услуги, FAQ и финальный CTA.
- На мобильном добавлена фиксированная панель «Позвонить / Оставить заявку».
- Убрана широкая таблица цен с горизонтальным скроллом на телефоне.
- Добавлены robots.txt, sitemap.xml, favicon, canonical, Open Graph и Schema.org.
- Добавлены отдельные privacy.html и consent.html.

Безопасность
- Старый логин/пароль полностью удалён из публичного HTML, JS и server.js.
- Чтение, изменение, удаление и экспорт заявок доступны только после серверной авторизации.
- Авторизация теперь использует случайную HttpOnly + SameSite=Strict cookie-сессию.
- Токены сессий в базе хранятся только в виде SHA-256 hash.
- Пароль администратора хранится как scrypt hash либо задаётся через ADMIN_PASSWORD.
- Добавлены security headers, ограничение размера запроса и rate limit для входа.
- PATCH/DELETE/logout требуют специальный same-origin custom header.
- Административные страницы и API не должны индексироваться.

Админка
- Иерархия сохранена: город → ЖК → адрес → заявки.
- Есть фильтры статусов, поиск и режим «Все адреса города».
- Добавлен CSV-экспорт.
- Добавлена карточка заявки с внутренней заметкой и датой следующего контакта.
- В сводке считается количество заявок, требующих контакта до конца текущего дня.
- На мобильном заявки выводятся карточками вместо широкой таблицы.

Запуск
======

1. Установить Node.js 18+.
2. В папке проекта выполнить:
   npm install
3. Запустить:
   npm start
4. Открыть сайт:
   http://localhost:3000
5. Админка:
   http://localhost:3000/admin/login.html

Первый вход в админку
=====================

Если ADMIN_PASSWORD не задан, при ПЕРВОМ запуске сервер:
- создаст login: airus-admin
- сгенерирует случайный пароль
- покажет пароль один раз в терминале
- сохранит в data/admin-auth.json только scrypt hash пароля

Сохраните пароль из терминала.

Если пароль потерян:
  npm run admin:reset

После сброса перезапустите сервер.
Можно задать другой login:
  npm run admin:reset -- my-login

Рекомендуемый production-запуск
===============================

Перед запуском в интернете лучше задавать данные администратора через переменные окружения:
  ADMIN_LOGIN=your-login
  ADMIN_PASSWORD=use-a-long-random-password
  NODE_ENV=production

При HTTPS NODE_ENV=production включает Secure для admin cookie.
Если приложение стоит за Nginx/Cloudflare/reverse proxy и нужен корректный req.ip:
  TRUST_PROXY=1

Не публикуйте папку проекта целиком как static files. Запускайте именно server.js; база и data/ находятся вне public/.

Перед публикацией обязательно
=============================

1. Юридические реквизиты
В исходном архиве нет полного наименования ИП/ООО/ФИО оператора, ИНН/ОГРН и адреса. Поэтому они не выдуманы.
Заполните сведения об операторе в:
- public/privacy.html
- public/consent.html

Согласие вынесено в отдельный документ и отдельную отметку формы. В базе сохраняются consent_at и consent_version.

2. Реальные фотографии
В исходном архиве реальных фотографий выполненных объектов не было. Вымышленные «кейсы» удалены, чтобы сайт не создавал ложного впечатления.
Секция «Что выполняем на высоте» сейчас использует имеющиеся SVG-иллюстрации. Для максимального доверия замените:
- public/assets/service-windows.svg
- public/assets/service-facade.svg
- public/assets/service-roof.svg
- public/assets/service-mount.svg
на реальные фотографии объектов (можно оставить те же имена или поменять src в public/index.html).

3. Персональные данные и размещение сервера
Если форма используется для сбора данных граждан РФ, до публичного запуска проверьте обязанность уведомления Роскомнадзора об обработке персональных данных и внесения оператора в реестр.
База, в которой происходит запись/накопление/хранение таких данных, должна размещаться с учётом требований российского законодательства о локализации персональных данных. Для этой сборки database.sqlite должна находиться на сервере, соответствующем этим требованиям.

4. Домен
SEO сейчас настроено на https://airus74.ru/ по e-mail manager@airus74.ru из исходного проекта.
Если реальный домен другой, замените airus74.ru в:
- public/index.html
- public/privacy.html
- public/consent.html
- public/robots.txt
- public/sitemap.xml

Проверка синтаксиса
===================

npm run check

База
====

Файл database.sqlite сохранён. При первом запуске недостающие поля добавляются автоматически:
admin_note, next_contact, consent_at, consent_version, source.
Перед production-развёртыванием сделайте резервную копию database.sqlite.
